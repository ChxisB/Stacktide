# Log - 03 gitlab-integration

## 2026-10-17 GL-1
- `packages/gitlab` (`@orch/gitlab`): `createGitlabClient({baseUrl, auth, ...})` with `request(method, path, {query, body})` and `paginate(path, query)` (async generator), plus `GitlabError` with `kind` (`unauthorized | forbidden | not_found | conflict | invalid | rate_limited | server | timeout | network | unexpected`), `status` and `retryAfterMs`. Methods for projects, MRs, pipelines and variables (GL-2..4) build on these two calls. `request` returns `unknown` by default so callers must validate/map to domain types.
- **API notes checked against docs.gitlab.com** (no target instance is known yet, so the exact version is unverified; GL-5's opt-in real run is where that gets confirmed): offset pagination default 20 / max 100 `per_page`; keyset needs `pagination=keyset` + `order_by` + `sort`; the `Link` header carries `rel="next"` and is absent on the last page (keyset also sends `X-Next-Cursor`); a 429 carries `Retry-After` in seconds (the client also accepts an HTTP date) alongside `RateLimit-*`; auth is `PRIVATE-TOKEN` for personal/project/group tokens and `Authorization: Bearer` for OAuth.
- Behaviour: auth strategies `private-token` and `oauth`; per-attempt timeout (15s, covers the body read); up to 3 retries; 429 is retried for every method (the request was refused), 5xx/timeout/network only for GET/HEAD/PUT/DELETE (a POST may have been applied: its `timeout`/`network` errors mean "outcome unknown"); backoff 500ms x 2^n with jitter; a wait (Retry-After included) above 30s fails at once as `rate_limited` carrying `retryAfterMs` so the job queue can reschedule instead of blocking a worker.
- Safety: token is required, 8+ chars; `baseUrl` must be https (http only for loopback unless `allowInsecureHttp`), without embedded credentials; redirects are never followed (a custom auth header would survive a cross-host redirect); the error names where a redirect pointed (origin + path only); `Link: next` URLs are rebuilt on the configured origin and must stay under `/api/v4`; request paths cannot carry `?`, `#`, `\`, or dot segments and cannot change host; errors and logs carry method, path (never the query), status and GitLab's own short reason (truncated to 200 chars, HTML ignored) and every message passes through a token scrub. Tests assert the token never appears in any error message, stack, JSON or log line when GitLab echoes it back; breaking the scrub, the redirect mode or the POST-retry rule each fails a test (checked by mutation).
- Gate: `bun run check` green, 122 tests before review fixes, 125 after (38 in this package, a local `Bun.serve` fake, no network, backoff via an injected `sleep`).
- `/code-review` (medium) found 8; fixed: path with query/fragment/dot segments, `per_page: undefined` overriding the default, tiny tokens, redirect gave no hint, `Link` could leave the API path, unknown-outcome semantics documented. Not changed: PUT/DELETE are still retried after an ambiguous failure, because a replay changes the outcome only for DELETE (404 for what was already removed): callers (GL-4, SYNC) treat 404 on delete as already gone; documented in `client.ts`. Not done: 408/425 are `unexpected` rather than retried. The completion-doc finding refers to a home-directory CLAUDE.md rule; the factory writes one per feature (Phase 4), not per task.
- Security (inline; `/security-review` unusable, see FND-4): this is the token-handling surface. No new dependency. Open limits: a token echoed URL-encoded or transformed by GitLab would not be scrubbed (GitLab tokens are `[A-Za-z0-9_-]`, so encoding is the identity); `paginate` has no page cap beyond loop detection (the server is trusted); `GitlabError.status`/`kind` reach callers, who must not forward `message` blindly into API responses beyond what GL-6 decides.
- Follow-ups: GL-2..4 add the typed methods and the shared contract suite (GL-5); real-instance verification is opt-in via `GITLAB_E2E_URL`.

## 2026-10-17 GL-2
- `createGitlab(opts)` / `gitlabApi(client)` returns a `Gitlab` object: `projects.{list,get}`, `groups.{list,get}`, `repository.{tree,getFile,compare,createBranch,commitFiles}`, `mergeRequests.{create,get,update,createNote,updateNote}`. Responses are validated with zod and mapped to domain types (`Project`, `Group`, `TreeEntry`, `RepoFile` with decoded text, `Comparison` with paths and change kind only, `Branch`, `Commit`, `MergeRequest`, `Note`); a payload of the wrong shape becomes `GitlabError("unexpected")` naming field paths, never values. `projects.list` uses keyset pagination in id order so an import can be repeated; `tree` is recursive keyset. Project refs are a numeric id or a full path (encoded as one segment).
- **Invariant 6 at the choke point:** `commitFiles` looks up the project and refuses its default branch (also `refs/heads/<default>`) before any write. It is defence in depth only: the name is read just before the write, so the default branch must also be protected in GitLab (PIPE/GL-7 should check or set that). Costs one extra GET per commit. MRs can be created, edited, closed and reopened; merging is deliberately not offered.
- **Mock built here, finished in GL-5.** `@orch/gitlab/mock` (`createMockGitlab`) is an in-process `Bun.serve` fake with auth, keyset-style `Link` paging, a branch/file model, atomic commits, compare, MRs and notes; later GL tasks add their endpoints to it, GL-5 adds failure injection and the real-instance switch. `contract.ts` is the suite every target must satisfy; `mock.contract.test.ts` runs it against the mock. Contract writes only to `orch-contract-*` branches and closes the MRs it opens; it has no `deleteBranch`, so a real sandbox run leaves those branches behind (GL-5 documents or adds cleanup).
- **Mock fidelity is from docs and memory, not from a real instance.** Least certain, to confirm in GL-5's real run: tree of a non-existent `path` (mock: empty list; the reviewer believes 404), 409 for a second open MR on one branch, 400 for an MR with equal source and target, 400 for `start_branch` on an existing branch. GL-7 must treat both empty and 404 as "absent" until then.
- Gate: `bun run check` green, 144 tests (57 in this package). Mutations checked: guard disabled fails the contract and the unit test; a non-atomic mock commit fails the atomicity test.
- `/code-review` (medium) found 9; fixed: `refs/heads/` bypass of the guard and documented its limits, tree `type` and MR `state` now enums (a new value fails decoding instead of falling through a switch), mock `start_branch` on an existing branch and equal-branch MRs, contract cases for both. Not done: memoising the default-branch lookup (commits are rare), branch cleanup (see above), reopen-conflicts in the mock. Completion-doc finding is the home-directory CLAUDE.md rule; the factory writes one per feature.
- Security (inline): no new secrets handling beyond GL-1's client; file contents flow to callers, so GL-7 and PIPE must not log them; commit messages and paths are caller-supplied. New dependency: `zod` 4.6.7 (already pinned elsewhere).

## 2026-10-17 GL-3
- `Gitlab` gains `pipelines.{trigger,get,jobs,retry,cancel}` and `ci.lint`. `trigger(project, ref, variables?)` sends `variable_type` (`env_var` | `file`); `jobs` is a paginated generator. Pipeline and job `status` is an enum where an unfamiliar value reads as `unknown` (a status GitLab adds later does not fail the response); `isFinished(status)` is true only for `success | failed | canceled | skipped` (`manual`, `scheduled` and `unknown` are not final, so a poller needs its own deadline).
- **`ci.lint` returns a typed result** `{valid, errors[], warnings[], mergedYaml|null}`: invalid config is a normal result, not an exception. It uses `POST /projects/:id/ci/lint`, which needs GitLab 15.7+ per the docs (target version unknown, GL-5's real run confirms). `dryRun` and `ref` are passed through; the mock ignores them.
- **Secret-safe trigger variables.** New client option `request(..., {redact: string[]})`: those values (4+ characters) are removed from GitLab's reason text and from network error text before truncation, in one longest-first pass, also in their JSON-escaped spelling (an object reason is re-serialised). Only GitLab's words are scrubbed, so a value like `POST` cannot mangle the fixed part of the message. `trigger` passes every variable value. Known limit: values under 4 characters are not scrubbed (a replace that short would mangle messages), documented on `PipelineVariable.value`. Zod decode errors name field paths, never values (GL-2 test), so the response path needs no scrub.
- Mock: pipelines, jobs derived from `.gitlab-ci.yml` on the ref (`Bun.YAML.parse`), manual jobs, retry and cancel (a finished pipeline stays as it is), project CI lint; helpers `pipelineVariables(id)` and `finishPipeline(id, status)` for tests. Trigger variables are kept for tests only and never returned, as in GitLab. Contract cases (trigger/get/jobs/cancel/retry on a manual-only pipeline so no runner is used; unknown ref `invalid`; unknown pipeline `not_found`; lint valid, no-script, broken YAML) run against the mock now and the real sandbox in GL-5. The contract commits `.gitlab-ci.yml` only on `orch-contract-*` branches.
- **Mock fidelity unverified:** status after cancel/retry of a manual-only pipeline on a real instance, the exact error texts, 400 vs another code for a missing ref or CI file, and lint of `include:`/`extends:` (the mock returns the input as `merged_yaml` and does not resolve them). The contract asserts only what GitLab documents.
- Gate: `bun run check` green, 155 tests (68 in this package). Mutations checked: dropping `redact` fails two tests; scrubbing after truncation instead of before fails the span test.
- `/code-review` (medium) found 8; fixed: scrub after truncation and JSON-escaped values, sequential-replace mangling (single pass, reason text only), mock cancel/retry on finished pipelines, doc of the short-secret limit and of `isFinished`. Not done: mock lint resolving `include` (see above).
- Security (inline): handles pipeline variable values, which are secrets. They go only in the request body, never in URL, logs or `Pipeline` results; tested for results and errors. New dependency: none.
