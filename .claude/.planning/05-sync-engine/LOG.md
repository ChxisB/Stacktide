# 05 Sync Engine - Log

## 2026-10-17 SYNC-1
- New package `packages/sync` (`@orch/sync`, no dependencies, D10 layout): `SyncAdapter<Config> { type; capabilities; validate(config); connect(config): Remote }` and `Remote { read(); create(item); update(item); delete(ref) }`. An item is `{ key, scope, value, secret }`; `value` is `null` when the target hides it (`canReadValues: false`), scope `*` (`ALL_SCOPES`) when the target has none. `read` is ordered by key, then scope, by code unit. `SyncError` kinds: `invalid_config`, `invalid`, `unsupported`, `not_found`, `exists`, `unmaskable`, `failed`; a message may name key and scope, never a value, a credential or the config. A call that can never work (`invalid`, `unsupported`, `unmaskable`) fails as that before existence is asked, so `not_found`/`exists` always mean the item. SPEC.md "Design" updated to this contract (it had `read(scope)` and bound adapters; nothing in the task list changed).
- `fakeAdapter(caps)` (exported from the package): in-memory targets by `store` name, capability switches (hidden values, no scopes, no masking), `stores` exposed so a test can edit a target "by hand" (drift tests later).
- `runAdapterConformance(label, setup)` (`@orch/sync/testing`, imports `bun:test`): 16 tests every adapter must pass, run against five fake variants (everything, hidden values, no scopes, no masking, bare): config validation (no echo of the config), empty read, exact values (lines, quotes, spaces, references, unicode), `exists`, update replaces and is idempotent, `not_found` for update/delete and no create by update, delete only that item, ordering, read returns a copy, scope isolation with no fallback to `*` and no prefix or wildcard matching, key matched as a whole, secret flag round trip and refusal without masking, hidden values are `null`, empty key/scope invalid, no failure carries a value (canary), targets do not see each other. `setup` must give an empty, separate target on every call.
- Tests: 82 (16 x 5 variants + 2). New workspace entry in `bun.lock`.
- Mutations: 30 checked on the fake against the suite (create/update/delete branches, scope fallback, prefix, key prefix/extension/case, ordering, locale order, hidden values, live copies, shared stores, empty key/scope, scope and masking checks, error messages with values or the config, secret flag, check order). 4 survived at first (a prefix mutant aimed wrong, the config echo, key whole-match, ordering of checks): the suite now tests them; none left.
- `/code-review` (medium) found 8. **Fixed:** the "no failure carries a value" test ran its calls concurrently and let must-fail calls pass: now in turn, must-fail and may-fail separated; the SPEC contract text updated; the order of `invalid`/`unsupported` against `not_found` is now stated and tested; `./testing` now exports the suite only, the fake is in the main entry (no `bun:test` in non-test code); the double import and the stray `idOf` export removed. **Dismissed:** "one target does not see another" assumes `setup` gives a separate target, which is the documented requirement (every other test needs an empty target too); an explicit `undefined` in `caps` is a caller bug, not worth a guard.
- Inline security review: no credential, no network, no real target; the suite proves no error carries a value or the config; plans do not exist yet.
- **Limits / follow-ups:** the contract has no `protected`, `raw` or variable-type fields; SYNC-3 adds them additively to `ItemInput`/`RemoteItem` and extends the suite; no batching (one request per item); no pagination or size limit on `read`; `failed` does not say whether a write took effect (the engine re-reads); the suite has never run against a real adapter; ordering by code unit may differ from what a target returns, so an adapter sorts itself.
- Gate: `bun run check` green, 1083 pass + 1 skip. New dependency: none.
