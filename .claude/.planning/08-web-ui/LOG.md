# 08 web-ui - LOG

## 2026-10-17 UI-1
- `apps/web` (`@orch/web`): React 19 on Bun HTML imports (D11), the typed client from `@orch/api-client`, TanStack Query, **hash routing** (`#/path`, so the API's own paths can never collide with a page). `src/api.ts` (`call` turns an Eden answer into data or an `ApiError` carrying the API's own problem text, status 0 for "no answer"; refuses a non-JSON or `null` body), `auth.tsx` (`AuthGate`: pending, 401 shows the login page, any other error shows an error with retry; `useSignOut`), `shell.tsx` (skip button, nav with `aria-current`, user name, sign out, `ErrorBoundary` per page), `app.tsx` (`pages` array: each screen adds itself), `styles.css` (light and dark tokens), `server.ts` (`bun run web`).
- **One origin.** `startWeb` serves `/` as the page and proxies everything else to the API (`ORCH_API_URL`, default `127.0.0.1:3000`; `WEB_PORT`, default 3001), so the session cookie and the GitLab sign-in redirect work without CORS. Redirects pass through unfollowed (`redirect: "manual"`), `set-cookie` passes through, hop headers and `host` are dropped, the client's abort cancels the upstream request, an unreachable API is a 502. **`GITLAB_OAUTH_REDIRECT_URI` must be the web origin's `/auth/callback` when the app is used through the proxy** (the API takes the redirect URI from config only, and `return_to` is checked to be relative, so nothing else needs to change).
- **Test setup.** Web tests run in their own `bun test` (cwd `apps/web`, own `bunfig.toml` preload: happy-dom, then testing-library cleanup in a second preload because testing-library reads `document` at import); the root `bunfig.toml` ignores `apps/web/**`, and the root `test` script runs both (so `bun run check` covers the web). happy-dom replaces `fetch`/`Request`/`Response`/`URL`...: the preload restores Bun's own, because the real API runs in the same process. Screens are tested against the **real app on a real port over a real test database**, with a session made in the database (`src/testing.tsx`: `startBackend`, `signIn`, `mount`). Typecheck runs for the root and for `apps/web` (`tsc --noEmit -p apps/web`; the root tsconfig excludes it because it needs DOM types).
- Tests (30): signed out shows the login link (`/auth/login?return_to=/`) and no nav; an ended session is signed out too; an unreachable server is an error with "Try again" and never the login page, and retry works once the server is back; signed in shows nav, user, home, skip button; sign-out ends the session server-side (401 afterwards, one `auth.logout` audit row, hash reset, cache emptied); sign-out with an already-ended session still reaches the login page; a failed sign-out says so and stays signed in; hash route picks the page, marks it, ignores a query string, unknown is home; a throwing screen shows an alert in the page and the nav keeps working; retry on the boundary; skip button moves focus without changing the route. Styles: dark set overrides only known tokens and defines each colour token, every `var()` names a token, no raw colour outside the token sets, WCAG AA 4.5:1 for text/muted/accent/status pairs in both sets. API helper (6). Server (7): serves the page and a script and stylesheet that load, production mode by default, forwards method/path/query/cookie/body/host, compressed body arrives readable, redirect and cookie pass through, error status kept, 502 when down, **a path such as `//host/x` cannot send the request (and the cookie) to another host**, abort is forwarded, bad `WEB_PORT` refuses to start.
- Mutations: 46 (`run60`) over the proxy (path/query/method/headers/body/cookies/redirect/encoding/status/abort/dev default/port check), the auth gate and sign-out, `call`, the shell, router and style tokens. First round left `A10` (retry did nothing) and `R1` (query string in route) alive: tests added (R1's first test was racy: it saw the previous page still on screen, so the route change now starts from home). All killed except the no-op control.
- `/code-review` (medium) found 9. **Fixed:** the skip link (`#main`) replaced the route with `#main` and threw the user to Home (now a button that focuses `<main>`); `typeof null` is `"object"` so a `null` 200 body reached screens as data (now refused); the route stayed after sign-out (reset); `startWeb` defaulted to dev mode and `WEB_PORT` was unchecked (production default, validated); no abort forwarding (added). **Rejected:** no path allowlist or CSRF check in the proxy (it adds no surface the API's own port lacks: the cookie, `Origin` and content type reach the API unchanged, and the API's JSON-only rule still applies); absolute-URL redirects from the API (its redirect URI is config, `return_to` is relative); the chained `test` script (a failing root run fails the gate anyway); cleanup hash-reset race (testing-library unmounts first).
- **Self-found, before the review:** the proxy resolved the request path with `new URL(path, api)`, so `GET //evil.test/x` went to `evil.test` with the session cookie. Now only pathname and search are taken from the request (test and mutation `S1` pin it).
- Inline security review: no secret is handled in the UI yet. The session cookie is `HttpOnly` on the API's side and only travels through the proxy; the login link is a fixed relative URL; error text is the API's problem text (never the request); `call` never repeats a non-JSON body. Limits: the dev/proxy server is not a hardened edge (no TLS, no rate limit, no header allowlist beyond hop headers); feature 13 puts a real reverse proxy in front.
- **New dependencies (all needed to have a UI at all, D11):** `react`, `react-dom` (the UI), `@tanstack/react-query` (server state: caching, retries, invalidation, instead of hand-rolled effects), dev: `happy-dom` + `@happy-dom/global-registrator` (a DOM for component tests; avoids a browser for unit tests), `@testing-library/react|dom|user-event` (query by role and name, which is also an accessibility check), `@types/react*`. - **REVIEW:** (1) **the visual direction (colours, type, spacing, layout) has not been approved** (task asks for the user's check before UI-2); it is token-driven (`styles.css`), so a change is one file. ## 2026-10-17 UI-3
- **Screen.** `variables.tsx`, page `#/variables`: pick a project (a `<select>` when there are several), then a table with a row per key and a column per environment (`<caption>`, `rowheader` = key, `columnheader` = environment). Each cell is the set the API resolves for that environment (`resolved-variables`), with where it comes from: **Set here**, **Overrides project|organization**, **From project|organization[, overrides organization]**, a kind tag (secret/file), **reads a secret**; an unset cell says "Not set" with a Set button; a key that cannot be filled in says why in its place. ## 2026-10-17 UI-4
- **Screens.** Each variable cell has a **History** button: a versions table (version, who as kind + short id, when in UTC with a `<time dateTime>`, why, a "Current" tag on the newest, a **Restore** button on the rest). No value is shown: the history route carries none. Restore asks for an optional reason, says that it adds a new version (the later ones stay) and, for an inherited (project or organization) cell, that it changes the value everywhere it is passed down. The versions are read afresh each time (`gcTime: 0`), so a restore made a moment ago is listed. **Import variables** (idle row): a `.env` or JSON text pasted or chosen from a file (≤ 1 MiB, format by file name), kind of every value, where it applies (shared `AppliesTo`: project, one environment, organization), "Replace values that differ". **Preview** (dry run) lists each name with its kind and result and what is left out (line numbers only); **Apply import** appears only after a preview of the same text and options that has something to create or change, and any edit drops the preview. A reply to an earlier text is dropped (`edits` counter). While saving, one `<fieldset disabled>` holds the text, options and file, and the buttons are disabled, so a request cannot be sent twice or change under itself. The grid reloads (and cells remount) before the summary appears.
