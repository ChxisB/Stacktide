# 08 web-ui - LOG

## 2026-10-17 UI-1
- `apps/web` (`@orch/web`): React 19 on Bun HTML imports (D11), the typed client from `@orch/api-client`, TanStack Query, **hash routing** (`#/path`, so the API's own paths can never collide with a page). `src/api.ts` (`call` turns an Eden answer into data or an `ApiError` carrying the API's own problem text, status 0 for "no answer"; refuses a non-JSON or `null` body), `auth.tsx` (`AuthGate`: pending, 401 shows the login page, any other error shows an error with retry; `useSignOut`), `shell.tsx` (skip button, nav with `aria-current`, user name, sign out, `ErrorBoundary` per page), `app.tsx` (`pages` array: each screen adds itself), `styles.css` (light and dark tokens), `server.ts` (`bun run web`).
- **One origin.** `startWeb` serves `/` as the page and proxies everything else to the API (`ORCH_API_URL`, default `127.0.0.1:3000`; `WEB_PORT`, default 3001), so the session cookie and the GitLab sign-in redirect work without CORS. Redirects pass through unfollowed (`redirect: "manual"`), `set-cookie` passes through, hop headers and `host` are dropped, the client's abort cancels the upstream request, an unreachable API is a 502. **`GITLAB_OAUTH_REDIRECT_URI` must be the web origin's `/auth/callback` when the app is used through the proxy** (the API takes the redirect URI from config only, and `return_to` is checked to be relative, so nothing else needs to change).
- **Test setup.** Web tests run in their own `bun test` (cwd `apps/web`, own `bunfig.toml` preload: happy-dom, then testing-library cleanup in a second preload because testing-library reads `document` at import); the root `bunfig.toml` ignores `apps/web/**`, and the root `test` script runs both (so `bun run check` covers the web). happy-dom replaces `fetch`/`Request`/`Response`/`URL`...: the preload restores Bun's own, because the real API runs in the same process. Screens are tested against the **real app on a real port over a real test database**, with a session made in the database (`src/testing.tsx`: `startBackend`, `signIn`, `mount`). Typecheck runs for the root and for `apps/web` (`tsc --noEmit -p apps/web`; the root tsconfig excludes it because it needs DOM types).
- Tests (30): signed out shows the login link (`/auth/login?return_to=/`) and no nav; an ended session is signed out too; an unreachable server is an error with "Try again" and never the login page, and retry works once the server is back; signed in shows nav, user, home, skip button; sign-out ends the session server-side (401 afterwards, one `auth.logout` audit row, hash reset, cache emptied); sign-out with an already-ended session still reaches the login page; a failed sign-out says so and stays signed in; hash route picks the page, marks it, ignores a query string, unknown is home; a throwing screen shows an alert in the page and the nav keeps working; retry on the boundary; skip button moves focus without changing the route. Styles: dark set overrides only known tokens and defines each colour token, every `var()` names a token, no raw colour outside the token sets, WCAG AA 4.5:1 for text/muted/accent/status pairs in both sets. API helper (6). Server (7): serves the page and a script and stylesheet that load, production mode by default, forwards method/path/query/cookie/body/host, compressed body arrives readable, redirect and cookie pass through, error status kept, 502 when down, **a path such as `//host/x` cannot send the request (and the cookie) to another host**, abort is forwarded, bad `WEB_PORT` refuses to start.
- Mutations: 46 (`run60`) over the proxy (path/query/method/headers/body/cookies/redirect/encoding/status/abort/dev default/port check), the auth gate and sign-out, `call`, the shell, router and style tokens. - Inline security review: no secret is handled in the UI yet. The session cookie is `HttpOnly` on the API's side and only travels through the proxy; the login link is a fixed relative URL; error text is the API's problem text (never the request); `call` never repeats a non-JSON body. Limits: the dev/proxy server is not a hardened edge (no TLS, no rate limit, no header allowlist beyond hop headers); feature 13 puts a real reverse proxy in front.
