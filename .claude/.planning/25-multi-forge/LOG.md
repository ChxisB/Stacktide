## 2026-10-22 - FRG-11 the GitHub client and its mock - done (built before FRG-10)
- **Order:** FRG-11 before FRG-10. FRG-10's connection test calls a representative endpoint per permission, so it needs a client; FRG-11 depends only on FRG-9.
- **What:** new workspace package `@orch/github` (`packages/github`). `createGithubClient({ baseUrl, token, ... })` with `request`, `paginate` (follows `Link: rel="next"`; a list GitHub wraps in an object is named as `items`) and `download` (capped). Every request sends `Authorization: Bearer`, `X-GitHub-Api-Version: 2022-11-28`, `Accept: application/vnd.github+json` and a `User-Agent`; redirects are not followed (a 301 names where, origin and path only). `apiRootOf`: `github.com` and `api.github.com` -> `https://api.github.com`; any other host -> `<origin><path>/api/v3` (GitHub Enterprise Server). Paths must start with `/` and carry no query, fragment or dot segments; a `Link` that leaves the API, does not advance, or points at another host is refused or read as a path of the configured host (the token never leaves).
- **Errors:** `GitlabError` kinds through `kindOfStatus`, as the forge interface still has one error type (FRG-9 shortcut). New: a **403 with `retry-after`, or with `x-ratelimit-remaining: 0`, and any 429, is `rate_limited`**; the wait is `retry-after` (seconds or an HTTP date), else until `x-ratelimit-reset`, else a minute. Longer than `maxRetryDelayMs` (30 s) it throws with `retryAfterMs` set. A refused-for-limit request did nothing, so any method retries it; 5xx, timeout and network retry only for GET/HEAD/PUT/DELETE, as in the GitLab client.
