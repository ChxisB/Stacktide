## 2026-10-21 - FLD-3 Folders in the database - done
- **Migration 0058** (`variable_folders`, additive: a new table, no existing row touched) with the hand-appended `variable_folders_updated` trigger. Table: id, organization, project, `path`, `deleted_at`, timestamps; a unique partial index on live `(project, path)`; a composite foreign key that keeps a folder in its project's organization (cascade with the project); a check that `path` is one to five `/segment`s of `a-z 0-9 - _`, 1-32 characters each.

- **Locks, because the table has no parent column:** `variable_folders` stores a path, not a parent id, so the database cannot enforce "the parent exists". `createFolder` selects the parent `FOR SHARE`; `renameFolder` locks the whole subtree `FOR UPDATE` before its single `UPDATE ... SET path = to || substr(path, n)`; `deleteFolder` locks the folder `FOR UPDATE` and refuses when a live sub-folder exists. Without the subtree lock a create under a descendant could land after the UPDATE's snapshot and keep its old path. Prefix tests use `starts_with`, not `LIKE`, because `_` is a LIKE wildcard and legal in a folder name.
- **`bad_name`:** a name such as `a/b` would pass the path check as two levels, so `createFolder` and `renameFolder` test the name against `FOLDER_PATTERN` first and return `bad_name`.
- **Gate:** `bunx biome check .` (the one existing info in `limits.test.ts`), `bun run typecheck`, `packages/db` 733 pass, and `bun test --env-file=.env.example packages apps/api apps/cli`: **5685 pass, 0 fail**. With `force` it goes ahead and the audit row says `forced: true, breakCount`.

A move to where the variable already is succeeds and is audited with `fields: []` (the audit plugin makes a 2xx without an audit row a 500, so a no-op must still write one).
