## Decisions to review (REVIEW-tagged in the LOG; the complete lists are there)

- **Audit (GOV-1, 13 items):** **append-only now holds against platform bugs, not against whoever holds the database credentials** (the `orch.audit_purge` setting; forward the log off-box via GOV-4 if that matters); lowering retention has no grace period or preview; per-round `audit.purge` events are noisy and age out; export cursors are not bound to their filters; CSV `'` prefix alters data; events of a deleted organization are never purged; audit read is org-admin only, no auditor role.
- **Protected environments (GOV-2, 17 items):** direct writes to a protected environment are refused rather than converted into requests; only the environment's own variables are gated (inherited org/project ones are not); protection is enforced in route handlers, not a DB trigger (a structural test guards new write paths); approvers see key names, not values; identity is by `userId`, so two accounts of one human are not detected; pending values are sealed with the project DEK, so key rewrap must include them; fixed 7-day lifetime; no author withdraw.
- **Apply approvals (GOV-3, 19 items):** IaC gating follows the repo-declared `stack.yml` `environment` and **a merge request can remove it**; the sync gate is conservative (any mapped protected environment gates every apply of the target); auto-sync silently does nothing for gated targets; asking needs only the developer role and the applier need not differ from the approver; a subset IaC apply consumes the whole approval; protection state is read without a lock at apply time; duplicate open requests are capped by a count taken without a lock.
- **Forwarding (GOV-4, 18 items):** **an event is sent once its id is 30 s old, so a transaction open longer can commit behind the cursor and is never forwarded**; syslog has no acknowledgement; DNS rebinding is still open for the HTTP kinds; retention can purge unforwarded events if a sink lags longer than the kept window; org-wide only (no per-project or per-action filter); collectors receive `ip` and metadata; a batch is sent while a transaction and a row lock are held; **deleting a sink forgets its place** (starting again from `now` skips what was written meanwhile, from `start` replays the log); an existing forwarding cannot be moved without DELETE first; a failing sink retries for ever (backoff capped at 1 h) with no alert.

## Findings that matter beyond this feature

- **`toMatchObject` ignores `Date` values in Bun 1.4.2** (also noted in the feature 10 doc); worth a grep of older tests.
- `notify.test.ts` (POL-2) had a time bomb: a fixed clock of 2026-10-18 12:30 UTC against rows stamped with the real clock. Fixed in GOV-3 without removing an assertion; the same fixed date appears in other test files that drive their own clock and pass.
- New always-on worker queues (`audit.purge`, `change_request.expire`, `audit.forward`) changed the queue-list expectations in `worker-main.test.ts` (disclosed in each LOG entry; nothing weakened). `ForwardFailure` lost a `name` override so existing `lastError` text stays unchanged.
- Mutation passes found real test gaps in every task (about 245 mutants over the feature); each survivor was killed by a stronger test or recorded as equivalent. Two were instructive: a "sink of another organization is refused" test that passed through a different error path (the primary-key conflict), and an ORDER BY that Postgres's planner hid in tests until the plan was forced.
