## Decisions to review (REVIEW-tagged in the LOG)

- **Authz model, new actions**: `sync.target.read` (project reporter), `sync.target.create|update|delete` (org admin: a target aims the connection's token at something), `sync.plan` and `sync.apply` (project maintainer), `sync.run.read` (project reporter). Drift is read with `sync.target.read`.
- **Migrations, all additive**: 0014 (`sync_runs`, `sync_run_items`), 0015 (`sync_runs.job_id`/`error`, the `sync_runs_one_applying` index, item results), 0016 (`jobs.dedupe_key` and its partial unique index), 0017 (`sync_target_drift`, `sync_targets.auto_remediate`).
- **Delete semantics**: project -> sync_targets CASCADE; connection -> sync_targets RESTRICT (409 `connection_in_use`); sync_targets -> sync_runs -> sync_run_items CASCADE (also while an apply runs); sync_targets -> sync_target_drift CASCADE.
- **Nothing deletes without a person**: auto-sync and auto-remediate plan with `ignore`; prune is a policy on a target and is applied only by a person's own plan and apply.
- **Equality oracle**: planning, and so a drift check, opens every secret of the project and the connection token; plan needs the maintainer role. There is no rate limit anywhere yet.
- **Worker keys**: the worker needs its own `ORCH_MASTER_KEYS`; without them the `sync.apply`, `sync.auto`, `sync.drift.tick` and `sync.drift` queues are not served and applies stay queued.

## Remaining risks and open follow-ups

- **Plans**: the digest covers variable ids, versions, keys, kinds and target settings, not values (a change outside versioning is not detected); `GET run` is unpaginated and there is no list-runs endpoint; every POST plan stores a run (no retention or rate limit); planning is not mutexed; unresolved keys are reported but do not block an apply; a value over 10,000 characters fails the plan (the platform allows 65,536); remote items in unmapped scopes are "unmanaged" and pruned under `prune`; one hard-coded target type; hidden values always plan as `update` (no last-applied fingerprint; an HMAC key needs a crypto design gate, to be done with the first hidden-value adapter).
- **GitLab adapter**: raw/protected/hidden drift is not read (a variable with `raw=false` and the right text is `noop`); `protected` is opt-in, so by default secrets are visible to pipelines on every branch; a Free-tier group ignores `environment_scope`; empty values and trailing newlines unverified on a real instance; a masked secret is readable by GitLab maintainers; the 10,000-character limit counts UTF-16 units; a timeout on POST is an unknown outcome; GitLab's "masked value equals another variable's name" rule is not checked (it answers `invalid`).
- **Targets API**: deleting an environment leaves its slug in the mapping (a new environment with that slug inherits the scope); the mapping check against a concurrent environment delete is not serialised; mapping uniqueness is exact text; a secret pasted into a config string field would be stored in the clear (no scanner); a given `config` replaces the old one and a patched mapping replaces the whole mapping; no body size limit (platform-wide).
- **Apply**: a create that finds the variable updates it, so a variable created on the target after the plan is overwritten; partial applies are not rolled back; `failed`-kind errors (a 403 included) are retried up to five attempts; no heartbeat, so an apply past the five-minute lock loses it (the next attempt continues from the recorded lines); a stuck run is ended by the next apply on that target or after an hour; secrets are opened twice per apply (endpoint and job); jobs are not pruned.
- **Auto-sync**: a timer from the first change, not a sliding debounce (at most 30 s); an organization-level change fans out to all its auto targets; a busy target is planned again every 30 s with no cap; **no protected-environment flag exists yet, so GOV-3 must make auto-sync skip those**; a plan refused with a 4xx is only logged.
- **Drift**: the status is as of `checkedAt` (a config, mapping or policy change leaves the old result until the next tick; a failed check keeps the old result and its time); drift is what an apply would write, so unmanaged remote items count only under `prune`, and pending unsynced variable changes also show as drift; a target with only deletes stays `drifted`; remediation is queued again on every tick while a write persists (an apply that never converges stores a run per tick); an apply that starts during a check can be seen as drift once; two concurrent checks of one target may audit the same change twice; `DRIFT_CHECK_SECONDS` is worker-wide and workers with different values overwrite the shared schedule; every target of every organization is planned each tick; one INSERT per target at fan-out.
- **Platform finding**: the database driver stores `jsonb` as a JSON string scalar, so SQL JSON operators (`payload->>'x'`) match nothing; filter in code until this is fixed at the db layer.
- **Mutation survivors left on purpose**: SYNC-6 S19/S20 (unreachable defensive branches), SYNC-7 V7/X2 (equivalent). Every other mutant checked was killed.
