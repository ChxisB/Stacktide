## Decisions to review (REVIEW-tagged in the LOG)

- **Visual direction (UI-1 on):** colours, type, spacing and layout were never approved. It is token-driven, so a change is one file (`styles.css`).
- **Roles in the UI (UI-8):** roles now reach the UI only for Settings, through the new `GET /organizations/:orgId/access` (no rule changed, but it adds to the authz surface). Variables, Sync, Pipeline and Status still show every control to every role and show the API's refusal.
- **Pipeline wizard (UI-6):** "ours" is decided by the file starting with the generated header, so a hand-written file that begins with that header would have its content shown to an org admin in the diff. Comparing with the hash of the last applied render would be stricter.
- **Status (UI-7):** the page shows the newest run per branch, not per environment, because nothing maps an environment to a branch. Retry is one click with no confirm.
- **Connections (UI-8):** deleting one destroys its stored token (the API's existing behaviour; only a confirm was added).
- **Variables matrix (UI-3):** it shows the existence and level of every secret to anyone who can read variables, as the API does.
- **Sync (UI-5):** the new last-run route reuses `sync.run.read`; no new action.
- **Hash routing and the proxy (UI-1):** deep links are `/#/variables`; the proxy dev server is how web and API share an origin until feature 13.

## Remaining risks and open follow-ups

- **UI-1:** the proxy is not a hardened edge (no TLS, no rate limit, no header allowlist beyond hop headers).
- **UI-2:** no groups browse endpoint (projects are browsed flat, with search); no create-organization UI; a member cannot read connections and cannot import; the organization list caps at 2000; a platform admin with no GitLab-group role sees no organization.
- **UI-3:** a description can only be set when adding; a plain value that reads a secret is revealed as its raw stored text; a member cannot see "overrides organization"; the 15 s reveal time is a constant.
- **UI-4:** no import source other than pasted text; restoring a secret is blind; actors show as a kind and a short id.
- **UI-5:** no screen creates or edits a sync target; the drift badge lags an apply until the next check; a plan is rendered without paging; polling is a fixed 1 s.
- **UI-6:** inline mode only (no include mode, overrides or environments in the form); a number parameter is text converted at send; only the newest version of a template is offered.
- **UI-7:** the 50 newest branches only; fixed 5 s polling with no back-off; one project at a time.
- **UI-8:** no members list (the platform has no group-member listing API and exposing one is a privacy decision); no audit viewer (GOV-1 builds it); scopes are typed as text; token lifetimes are four fixed choices; a connection cannot be edited; a role change shows after the next load, behind the API's 5 minute membership cache.
- **UI-9:** `Only dev` and the other labels are the screens' own text, so a copy change breaks the journey on purpose.
