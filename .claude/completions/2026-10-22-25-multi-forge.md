# 25 multi-forge - built 2026-10-22 (ADR-0019 and D16 still Proposed; nothing run against a real GitLab or GitHub)

The platform now works with **more than one forge**: any self-managed GitLab (several at once, each with its own CA and version), GitLab.com, and **GitHub.com** (Actions as the runner). A project knows which connection it came from; a connection has a type (`gitlab` or `github`); the code that used to call GitLab directly goes through a `Forge` interface with a contract suite that both adapters pass. GitLab behaviour and its tests are unchanged.

Everything was built on the recommended answers in the SPEC, under your blanket go to finish every open task. Nothing is committed. **Five tasks change the auth model** (FRG-5, FRG-6, FRG-23, FRG-33, FRG-25) and one adds a dependency (FRG-19): I built them on that go, because you said you would review afterwards. Each carries a flag below and in LOG.md. If you did not mean the go to reach them, these are the ones to look at first.

- **B, running things on GitHub (FRG-16, 17, 18, 29, 30, 31, 22, 32).** The Actions workflow for onboarding; the stack plan as data (`runPlan`, migration 0062); a static stack workflow for plan and one for apply with its approval gate (an Actions environment); starting and judging a run; the stack workflow delivered in the onboarding pull request when a platform address is configured (FRG-31); runs, approvals **observed** and plan/apply on a pull request (migration 0063, FRG-22/32).

- **New packages:** `packages/forge`, `packages/github`. **Migrations:** 0060 to 0065 (0060 changes which columns make a project unique, the rest are additive). **New dependency:** `libsodium-wrappers` 0.8.4 (FRG-19, for the sealed box; GitHub requires it). ## Reviews
- **Security review (by hand), per task**, in each LOG entry under "Security read". The built-in `/security-review` reads a git diff, and here the working tree mixes features 14 to 31, so it was not a useful unit; I read each task's own files instead. Auth tasks (FRG-5, 6, 23, 33, 25) and the sealed box (FRG-19) each have the longer reads.
- **No `/code-review` run** over the feature as a whole, for the same reason. Each task's diff was read against invariants 1 to 8.

## Not checked
- Anything on a real GitHub: PKCE on GitHub's authorize endpoint (confirmed only from the 2025-07-14 changelog), the `ref_protected` claim, the `workflow_dispatch` response, the sealed-box output, environment-read permissions, the `/runs/<job id>` redirect, and the payload fields listed in `docs/forge-seam.md` §8.
- Any GitHub Enterprise Server or Enterprise Cloud (`GITHUB_E2E_URL` accepts an address; nothing else is built for it; their OIDC issuers are not supported).
- The stack workflows were not linted with `actionlint`.
- The load behaviour of the role checks (about 3 GitHub calls per linked repository per person per 5 minutes).

## Left out, on purpose
- apply on merge for GitHub, fork pull requests (refused), a GitHub identity linked to an existing person, removing a GitHub identity, Bitbucket and Gitea (the seam is built so they can come later).
- On GitHub, a stack with an `environment`, policy, cost, DNS, pools or an environment-bound stack is **refused** with a message, not half-supported.
