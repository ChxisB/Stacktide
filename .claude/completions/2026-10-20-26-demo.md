# 26 demo - done 2026-10-20

`bun run demo` starts the real API and the real web page over a throwaway database and the mock GitLab, fills them with an organization (Acme) and prints one link that signs you in. `bun run demo:shots` writes a picture of every page in dark and light. Nothing is committed.

## What was built
- **DEMO-1** `apps/web/demo/seed.ts` and `server.ts`: org Acme with its owner (Ada Lovelace), a connection, projects `acme/web` and `acme/api` imported (`acme/docs` left for the import page), three environments, variables at each level, a worker pool. A second server on the next port issues a session and redirects to the app. Both servers bind `127.0.0.1`.
- **DEMO-2** Something on every page: nine pipelines on eight branches of `acme/web` in every state (real pipelines of the mock, so Retry works), state versions for two stacks, four findings, and a sync target applied once and then drifted by one change. The worker runs the real apply and the real drift check; a tick every 5 s stands in for the schedule, so an apply from the page reads "In sync" within seconds.
- **DEMO-3** `docs/demo.md` and a README line; a test checks every `bun run` in it is a script.
- **DEMO-4** `demo/shots.e2e.ts` and `demo/playwright.config.ts`: ten pages, two themes, 1280 wide, twenty PNGs in `apps/web/demo/shots/` (git-ignored). It also fails on a crash, a sideways scroll, a console error, a refused request or a page still loading.
- **DEMO-5** This delivery.
