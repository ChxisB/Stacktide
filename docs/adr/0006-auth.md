# ADR-0006: Auth - GitLab OAuth, scoped API tokens, GitLab OIDC for CI
Status: Accepted 2026-10-17 · Roadmap: D6

## Context
The team already lives in GitLab. Humans, scripts and CI jobs each need an authentication path.

## Decision
- Humans sign in with GitLab OAuth.
- Scripts and the CLI use scoped, revocable API tokens (stored hashed).
- CI jobs authenticate with GitLab OIDC `id_tokens`.
- Authorization is deny-by-default: every route declares a guard, every mutation writes an audit event (invariant 4).

## Consequences
- No password storage or user-management UI.
- Platform identity depends on GitLab availability.
- SAML is not planned. Sign-in through an organization's own OIDC identity provider is added by [ADR-0016](0016-external-identity-providers.md); multi-org tenancy is built.
- Changes to this model are a human gate.
